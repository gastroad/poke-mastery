# PokéMastery

Web-based Pokémon **knowledge game** (learn → challenge → earn badges → raise mastery → unlock harder challenges). Not a Pokédex, not a generic quiz. Unofficial fan project / personal portfolio. It should feel like playing a game.

## Architecture: 4 layers under `src/`

- `domain/` — **pure** game rules: question generation, answer judging, scoring, XP, badges, progress. NO React/Next/Zustand/Drizzle/Neon/Node/Browser imports. Everything is a pure function, unit-tested with Vitest.
- `client/` — browser code: React components, Zustand stores, hooks, Motion animations. NO db/repo/Drizzle/Neon.
- `server/` — server-only code: route handlers, server actions, repositories, services, auth, db. Use `import "server-only"`.
- `shared/` — used by both client & server: Zod schemas, request/response types, constants, env-independent utils.
- `src/app/` — thin Next.js App Router shell only (pages compose `client/`; route handlers delegate to `server/`).

### Dependency rules (enforced by ESLint `no-restricted-imports`)

Allowed: Client→Domain, Client→Shared, Server→Domain, Server→Shared.
Forbidden: Domain→(Client/Server/React/Next/Zustand/Node), Client→Server impl, Server→Client impl.

## Key invariants

- **Never trust the client.** On game end the client sends only a `PlayRecord { challengeId, seed, attempts }`. The server re-runs the same domain functions to recompute answers/score/XP/badges/progress and persists only the final result.
- **Deterministic questions.** `generateQuestions(rule, dataset, seed)` is pure & deterministic — same seed ⇒ identical questions (so the server can replay a game). Domain uses a seeded PRNG, never `Math.random()`.
- **Zustand holds session state only** (current question, progress, timer, combo, lives, input, status) — never game rules. Rules live in `domain/`.
- **Badges are data-driven.** Conditions are data in a catalog, judged by pure functions in `domain/badge`. Never hardcode badge conditions in UI.
- **Pokémon data is static reference data** in `src/data/*.json` (generated by `scripts/sync-pokemon-data.ts` from PokéAPI at dev time; sprites downloaded to `public/sprites/`). Never call PokéAPI during play. The DB holds user data only (progress, play_results, earned_badges).
- **Answers: Korean names only** (MVP), normalized (strip whitespace + NFC). Nidoran ♀/♂ accept both genders via a per-Pokémon accepted-answers set.
- **Anonymous play** works with no DB (localStorage only); persistence begins at login. No guest→account merge.

## Commands

- `npm run dev` — dev server
- `npm run test` / `npm run test:watch` — Vitest
- `npm run typecheck` — `tsc --noEmit`
- `npm run lint` — ESLint (includes layer-boundary rules)

## ⚠️ Next.js 16

This project uses **Next.js 16**, which has breaking changes vs earlier versions. Before writing Next-specific code (routing, server actions, config, caching), check `node_modules/next/dist/docs/`. See `AGENTS.md`.
